# 本地文件夹工作台后端需求

**文档状态：** 需求定义，尚未实现  
**依据：** `Cebian/entrypoints/local-folder/REQUIREMENTS.md`  
**适用范围：** 为 Cebian 本地文件夹工作台提供独立运行的本机文件服务

## 1. 目标与边界

后端是一个由用户在本机安装并启动的独立服务，通过 WebSocket 为 Cebian 扩展的 `local-folder` 页面提供配对、文件夹授权、目录浏览、文本文件读写、搜索、监听和变更通知。页面不直接访问任意本地路径，也不能启动或控制服务进程。

后端以本机文件系统为事实来源，负责每次请求的授权检查、路径边界校验、文件格式保真和版本冲突保护。客户端页面负责界面状态、标签页、编辑器、未保存草稿以及用户发起操作的交互。

本功能与 AgentMesh 现有 Codex Runtime、Worker、Session、Task、MCP Server、VFS 和聊天会话无关。首版不将文件访问包装为 Agent 工具，也不修改 AgentMesh 当前 HTTP MCP 服务。后端可以作为同仓库中的独立程序交付，但必须独立启动、配置和停止；其崩溃或升级不得影响 AgentMesh Runtime。

## 2. 术语和核心规则

- **服务**：本机运行的本地文件夹后端进程。
- **页面**：Cebian 扩展中的 `local-folder.html`。
- **授权根目录**：用户明确选择并授权给一个页面订阅的目录。
- **订阅**：页面在一次连接期间对一个授权根目录的活动访问关系。
- **相对路径**：以授权根目录为基准的路径；除首次选目录外，协议不得接受绝对路径。
- **文件版本**：服务端为读取和写入冲突检测生成的稳定版本标识。
- **隐藏规则**：只影响目录树展示。
- **停止监听规则**：阻止该路径进入文件监听、搜索和目录遍历结果。

所有文件系统操作必须限制在当前订阅授权根目录内。页面路径、最近使用记录、搜索结果和忽略规则均不能扩大授权范围。

## 3. 部署与进程生命周期

### 3.1 独立运行

1. 服务由用户或操作系统进程管理器显式启动，页面只连接服务，不负责启动服务。
2. 服务须提供可重复执行的安装、启动、停止、状态检查和卸载方式；具体交付形式（例如 npm 命令、独立可执行文件或桌面伴随进程）在实施设计中确定。
3. 服务启动失败必须输出可诊断错误并以非零状态退出，不得留下无法管理的后台进程。
4. 正常关闭时停止接收新连接，向客户端报告服务关闭，解除所有订阅并关闭文件监听器。
5. 非正常退出后，重启时不得恢复旧 WebSocket 会话或旧的活动授权；页面需重新连接并重新建立订阅。可持久化的配对凭据和最近目录按本需求另行处理。
6. 日志不得记录配对秘密、完整文件内容或未经脱敏的授权凭据。

### 3.2 网络监听

- 默认绑定 `127.0.0.1`，端口可配置；默认不得监听 `0.0.0.0` 或局域网接口。
- 服务公布 WebSocket URL 和实际监听状态。端口被占用、权限不足和配置无效时提供明确错误。
- WebSocket 握手需校验请求来源。仅来自 localhost、仅使用 WebSocket 或通过来源校验，都不能单独构成文件访问授权。
- 应只允许已知的扩展来源及受支持的本机管理客户端；开发模式允许的来源必须显式配置，不能默认放宽生产规则。
- 服务设置最大连接数、握手超时、空闲超时、消息大小、每连接请求速率和事件推送速率上限。

## 4. 配对、凭据和授权

### 4.1 首次配对

1. 新客户端连接后只能访问配对流程，不得枚举目录、读取最近目录的绝对路径或操作文件。
2. 首次配对由本机用户在服务端确认，或使用服务端生成的一次性短时配对码。配对码必须有足够随机性、短有效期、单次使用和失败次数限制。
3. 配对完成后服务向客户端签发不可预测的客户端凭据；凭据只能通过加密安全存储提供给页面，且不得放入 URL、普通日志或错误文本。
4. 配对码不可替代长期凭据；过期、重复使用、错误来源或超过尝试限制均应拒绝并返回机器可识别错误。
5. 服务重启后已配对页面可使用安全存储的凭据重新认证，但必须重新创建订阅。服务端凭据存储应限权，并支持轮换。

### 4.2 授权撤销

- 用户可在服务端撤销单个客户端或全部客户端授权。
- 撤销立即使凭据失效，关闭该客户端所有连接和订阅，停止向其推送事件，并拒绝后续请求。
- 页面必须收到可识别的授权撤销状态，清除本地配对凭据和该授权下的草稿恢复入口，并要求重新配对。
- 授权撤销不删除用户文件，不得因撤销凭据而自动删除文件系统数据。

### 4.3 页面和目录授权模型

- 配对授权只允许页面请求操作；它不自动授权任何文件夹。
- 每个活动页面订阅一个根目录。服务端对目录选择结果验证其为可访问目录，再为该订阅建立根目录授权。
- 同一个客户端可以在不同时间切换根目录；切换成功后旧订阅立即失效。切换失败或文件夹选择取消时，旧订阅保持有效。
- 不同页面可以分别选择不同根目录，也可以同时订阅同一规范化根目录；页面状态和订阅 ID 相互独立。
- 最近使用目录只保存选择辅助信息，不构成授权。重新打开时必须重新检查存在性和权限并创建新的订阅。
- 最近目录列表应按客户端隔离；移除记录不删除实际目录。

## 5. 文件系统安全和路径解析

### 5.1 根目录边界

1. 首次目录选择可接受本机文件夹选择器结果或用户输入的绝对路径；输入路径仅用于创建授权根目录。
2. 服务对根目录解析真实路径（canonical path），确认其存在、为目录且当前用户可访问，并返回不泄露额外系统信息的根目录摘要。
3. 订阅内所有操作只接收规范化相对路径。拒绝绝对路径、盘符/UNC 路径、空路径非法形式、NUL、路径穿越段、编码绕过、分隔符歧义和根目录自身的修改操作。
4. 每个请求都必须在执行前重新校验解析后的实际目标仍处于根目录内，不能只在打开目录时校验一次。
5. 检查须考虑符号链接、junction、Windows reparse point、大小写不敏感文件系统及路径规范化差异。禁止通过链接读取、写入、搜索或删除根目录外对象。
6. 对根目录内指向根目录内目标的符号链接，首版默认在树中标记但不可进入或跟随；除非后续安全设计明确允许并定义循环检测与重复路径语义。
7. 校验和操作之间存在竞态时，应使用安全的文件句柄/原子操作策略尽量避免 TOCTOU 越界；无法证明目标安全时失败关闭。
8. 错误响应不得泄漏根目录外路径、凭据或本机用户隐私信息。

### 5.2 名称和危险目标

- 新建、重命名名称必须是单个文件系统名称，拒绝分隔符、保留名称、非法字符、`.`/`..`、尾随点或空格等目标平台不支持的形式。
- 服务端重新校验名称合法性、目标目录可写性和重名情况；不得依赖页面校验。
- 默认不跟随符号链接执行修改或递归删除。
- 删除操作只能作用于确认后的订阅内目标，不允许删除授权根目录。

## 6. 目录查询、搜索和忽略规则

### 6.1 按需目录查询

- 列目录仅返回指定目录的直接子项，不要求递归扫描整棵目录树。
- 子项信息至少包含名称、相对路径、类型、可读/可写状态、符号链接标记及必要的文件元数据。
- 目录先于文件排序，同类按稳定的名称排序；排序规则应跨分页一致。
- 对不存在、无权限、路径越界、被忽略和非目录分别返回明确错误或状态，不得伪装成空目录。
- 支持请求取消、结果上限和分页/游标（若实施采用分页），避免单次响应超出消息限额。
- 定期校验已订阅及已展开目录以弥补文件系统事件漏报；校验范围和并发必须有界。

### 6.2 文件名搜索

- 搜索只匹配名称，不搜索文件内容；结果提供相对路径以区分重名文件。
- 搜索遵循当前订阅根目录、停止监听规则和授权状态，不能通过搜索访问不可遍历目录或链接外目标。
- 服务端限制结果数、扫描深度/工作量和耗时；支持取消过期查询及去重并发查询。
- 搜索结果必须标记不完整/截断状态，不得将部分结果伪装成完整结果。
- 大型目录可使用按需或可重建索引；索引不是权限边界，返回结果前仍需验证路径和当前规则。

### 6.3 忽略规则

- 服务提供读取、更新和校验忽略规则的能力，规则范围限制在订阅根目录相对路径。
- 隐藏规则只从目录树展示结果中过滤匹配项，不停止监听、索引或搜索；搜索是否隐藏结果由协议明确标记，不能误认为文件不存在。
- 停止监听规则必须阻止路径进入文件事件监听、目录递归校验和搜索索引，并从已有索引中移除其条目。
- 规则变更有递增版本；更新成功后返回新版本并通知订阅客户端刷新树和搜索结果。
- 规则语法、匹配优先级、目录继承、大小写敏感性和默认建议规则需在协议版本中固定说明。`node_modules`、`.git` 等可以预置为建议项，但用户必须能查看和修改生效规则。
- 规则变更不得删除或修改磁盘文件。规则无效时拒绝整次更新并说明具体规则错误。

## 7. 文件读取、文本格式和保存

### 7.1 读取

- 只提供文本内容读取，不提供二进制内容或预览。
- 服务端在读取前检查文件大小并执行固定上限；建议上限 5 MiB，正式实现需确定并在协议能力中公布。超过上限返回 `FILE_TOO_LARGE`，不得先将整个文件载入内存。
- 内容必须是有效 UTF-8。可识别并保留 UTF-8 BOM；无效 UTF-8 返回 `UNSUPPORTED_ENCODING`，不得有损解码后再允许保存。
- 返回内容、相对路径、BOM 状态、换行统计/策略、末尾换行状态、字节大小、可写状态和文件版本。
- 读取不得执行或解释 HTML、SVG、脚本或其他活动内容。文件类型判断不应只依据扩展名；无扩展名 UTF-8 文本可按文本读取。
- 文件在读取过程中变化、消失或权限变化时返回明确错误，不返回内容与版本不一致的伪成功响应。

### 7.2 文件版本和冲突

- 每次读取返回不透明版本标识，至少能检测内容、文件身份或相关元数据变化。实现可以使用内容哈希结合文件身份/元数据，但协议不依赖具体算法。
- 保存请求必须包含读取时的预期版本；服务端在提交写入前再次检查当前版本。
- 版本不同、文件已删除、重命名或目标身份变化时拒绝保存并返回 `VERSION_CONFLICT` 或明确目标状态；不得静默覆盖。
- 服务提供显式的冲突处理路径：重新读取磁盘版本，或经用户明确确认后以最新版本为基准执行覆盖。覆盖仍需携带当前版本，不能提供绕过竞态检查的无条件写入。

### 7.3 保存和格式保真

- 保存采用显式请求；服务端不得因内容变化自动写盘。
- 保存保持读取时的 UTF-8 BOM 状态、换行风格和末尾换行。混合换行文件应保留原有行级格式；若实现不能安全保留，必须在写入前明确拒绝或要求用户选择转换策略，不能静默规范化整个文件。
- 写入应避免半写入文件（例如同目录临时文件加原子替换，并在替换前后重新验证版本和目标），并尽量保留合理文件权限和时间属性；平台不支持原子替换时定义恢复策略。
- 保存成功返回新版本、实际路径、字节数及变更事件版本。失败时磁盘内容保持原状或返回可恢复的明确状态。
- 同一文件的并发修改串行化或通过版本检查保证只有一个预期版本写入成功；不同文件的操作不得被全局锁不必要地阻塞。
- 只读文件可以读取；保存时返回 `PERMISSION_DENIED` 并提供机器可区分错误。

### 7.4 新建、重命名和删除

- 新建文件仅创建空 UTF-8 文本文件；新建目录只创建单层目录，不隐式创建缺失的父目录。
- 新建、重命名和删除在服务端执行名称、权限、边界及冲突校验，失败不得产生部分操作。
- 重命名只允许同一父目录内改名，不提供移动功能，不覆盖现有目标。目录改名后服务推送旧、新相对路径及新版本信息。
- 非空目录删除必须由客户端显式确认递归删除。服务端提供准确条目数，或返回计数未知并要求确认未知范围；不得返回错误的确定数量。
- 删除请求携带目标版本/身份条件，防止确认后目标被替换。根目录不能删除或重命名。
- 文件系统实际操作成功后才发成功响应和权威变更事件；失败时页面所依赖的目录状态仍可通过重新查询得到真实结果。

## 8. 文件监听和多客户端同步

- 服务按规范化真实根目录复用底层 watcher；同一目录多个页面订阅时共享监听器，但每个页面有独立订阅 ID、授权状态和事件游标。
- 页面断开只解除自己的订阅；最后一个订阅解除后，服务在宽限期后关闭该目录 watcher 和不再需要的索引。
- 监听新增、修改、删除和重命名。若底层平台无法可靠识别重命名，允许表示为删除加新增；最终状态必须可重新查询恢复一致。
- 事件必须包含订阅 ID、相对路径、事件类型、单调递增序号和必要的文件版本/身份信息。事件不得包含完整文件内容。
- 对服务端发起的写操作，响应版本与 watcher 事件版本可关联，客户端能够幂等归并，不重复插入条目或回退到旧版本。
- watcher 事件可合并和限速；达到平台队列上限、发生溢出或无法确定事件范围时，发送 `RESYNC_REQUIRED`，页面重新查询受影响目录；影响范围不确定时重新同步根目录。
- 定期对已展开目录进行校验，补偿漏报。服务重启、目录移动/删除、权限失效和 watcher 建立失败必须发明确状态，不得伪装为空目录。
- 文件事件通知不构成额外授权；每次事件发布前确认订阅仍有效且路径仍在授权范围内。

## 9. WebSocket 协议要求

### 9.1 协议版本与消息包络

- 协议使用显式主/次版本号。连接阶段协商版本；主版本不兼容时拒绝并返回服务支持版本。
- 所有客户端请求有唯一 `requestId`；响应回显同一 ID。推送事件使用独立 `eventId` 和递增序号。
- 建议统一消息包络：

```json
{
  "protocolVersion": "1.0",
  "type": "request",
  "requestId": "uuid",
  "method": "directory/list",
  "params": {}
}
```

- 成功响应返回 `type: "response"`、对应 `requestId` 和结果；失败响应包含稳定的错误码、可读说明及是否可重试标记。
- 服务推送使用 `type: "event"`、`eventId`、订阅 ID、事件序号、事件名和数据。
- JSON Schema/运行时校验必须用于入站消息。未知方法、字段类型错误、超大消息和无效版本应得到协议错误；不得使服务崩溃。
- 协议必须有请求超时、客户端取消、服务端取消以及连接断开时请求清理的约定。

### 9.2 最小方法集合

| 类别 | 方法能力 | 说明 |
|---|---|---|
| 握手 | `hello` / `authenticate` | 协商版本，配对或使用凭据认证 |
| 配对 | `pair/begin`、`pair/complete` | 启动并完成一次性配对 |
| 状态 | `service/status` | 返回版本、运行状态、限制和授权状态 |
| 目录选择 | `folder/choose` | 打开本机目录选择器；取消不改变现有订阅 |
| 目录授权 | `subscription/open`、`subscription/close` | 建立/关闭一个页面的根目录订阅 |
| 目录查询 | `directory/list`、`directory/refresh` | 查询直接子项与目录版本 |
| 文件 | `file/read`、`file/create`、`file/save` | 读取、创建、按预期版本保存文本文件 |
| 修改 | `entry/rename`、`entry/delete` | 同目录重命名和受确认的删除 |
| 搜索 | `search/name`、`search/cancel` | 有界文件名搜索及取消 |
| 最近目录 | `recent/list`、`recent/remove` | 页面级最近目录选择辅助 |
| 规则 | `ignore/get`、`ignore/update` | 查询和更新隐藏/停止监听规则 |
| 事件 | 服务推送 | 文件变化、授权变化、订阅失败、重同步需求 |

方法命名可以在实现阶段调整，但每项能力和安全语义必须保留并纳入版本化协议说明。

### 9.3 错误码

错误码至少覆盖：`UNAUTHORIZED`、`PAIRING_REQUIRED`、`PAIRING_EXPIRED`、`PERMISSION_DENIED`、`PATH_OUTSIDE_ROOT`、`INVALID_PATH`、`NOT_FOUND`、`NOT_DIRECTORY`、`ALREADY_EXISTS`、`VERSION_CONFLICT`、`UNSUPPORTED_ENCODING`、`FILE_TOO_LARGE`、`IGNORED_PATH`、`RATE_LIMITED`、`REQUEST_CANCELLED`、`SERVICE_SHUTTING_DOWN`、`RESYNC_REQUIRED`、`PROTOCOL_VERSION_UNSUPPORTED` 和 `INTERNAL_ERROR`。

错误消息可面向用户，但机器分支判断必须依据稳定错误码；不得返回堆栈、令牌或越界路径细节。

## 10. 资源限制与可靠性

- 最大文件大小、消息大小、连接数、并发读写数、目录返回条目数、搜索工作量和事件队列上限均需可配置或有明确默认值，并通过服务状态/协议能力公布。
- 目录扫描、搜索和 watcher 恢复需使用有界并发；高事件量不得无限积压内存。
- 单个客户端超时或断开不得阻塞其他客户端及其他根目录。
- 服务异常必须记录结构化日志和可诊断原因；对外错误保持稳定且不泄露隐私。
- 最近目录、配对授权和忽略规则的持久化格式需要版本化、可校验，并能处理损坏数据。恢复失败时采取安全默认值并明确报告。
- 最近目录记录不得包含文件内容。日志和索引不保存完整文件内容；搜索索引只存执行文件名搜索所需信息。

## 11. 可观测性和运维接口

服务应提供本机可执行的状态检查，至少报告：服务版本、监听地址、协议版本、配对状态、活动连接数、活动订阅数、watcher 数、运行错误和资源限制。状态检查不得暴露凭据或文件内容。

日志至少包含连接建立/断开、认证结果（不含凭据）、配对/撤销、订阅生命周期、文件操作的结果类别、watcher 故障与重同步事件。涉及文件操作时可记录相对路径或脱敏标识；是否记录名称由隐私策略在实施阶段确定。

## 12. 测试和验收

### 12.1 协议与功能验收

1. 服务可独立安装、启动、停止、检查状态；默认只监听回环地址。
2. 未配对客户端不能查询路径、最近目录或文件；错误、过期和重复配对码均被拒绝。
3. 配对后可选择目录并逐级列目录；取消选择不切换订阅；最近目录重新打开时必须重新验证。
4. 同一目录的多个页面订阅共享底层 watcher，各自关闭不会影响其他页面。
5. 可按名称搜索未展开目录中的文件，结果有界、带相对路径且可取消。
6. 可读取 UTF-8 文本、识别 BOM/换行/末尾换行并返回版本；非 UTF-8 和超限文件被明确拒绝。
7. 可新建空文件和目录、按预期版本保存、同目录重命名和删除；重复目标、无权限和并发版本冲突返回稳定错误。
8. 含 BOM、CRLF、混合换行及末尾换行文件保存后保持约定格式；冲突或失败不会清除磁盘/用户内容。
9. 外部程序变更能通过事件同步；漏报、溢出或服务重启后客户端可按要求重新同步。
10. 隐藏规则仅控制展示；停止监听规则阻止监听、递归校验和索引/搜索，并在规则更新后生效。
11. 撤销授权立即终止连接和订阅，旧凭据不能重新连接。

### 12.2 安全验收

自动化测试必须覆盖路径穿越、绝对路径、盘符和 UNC 注入、符号链接/junction 越界、根目录删除/重命名、重名覆盖、竞态替换、伪造订阅 ID、跨客户端访问、未授权请求、请求洪泛、超大消息和 watcher 溢出。

测试确认所有越界请求失败关闭；攻击性输入不能读写根目录之外内容、泄露敏感路径或导致进程崩溃。

### 12.3 浏览器兼容验收

须在项目支持的 Chrome MV3 和 Firefox 构建中实测从扩展来源建立本机 WebSocket 连接、完成配对、断线重连和撤销授权。浏览器对本地网络、扩展来源或 CSP 的限制，应通过目标浏览器实测确认并记录部署要求。

## 13. 交付清单

- 独立本机服务及其版本化 WebSocket 协议说明。
- 安装、启动、停止、升级、卸载和故障排查说明。
- 默认配置及可调端口、资源限制和日志策略。
- 配对与授权撤销的人类可操作入口。
- 自动化单元、协议、安全和文件系统集成测试。
- Chrome MV3 与 Firefox 实测记录。
- 明确区分服务端存储的凭据/最近目录/规则，与扩展端未保存草稿。

## 14. 明确不在后端范围内

- 扩展页面布局、目录树交互、编辑器、标签和键盘快捷键。
- 页面草稿保存与恢复（由扩展本地存储负责）。服务撤销授权时只需通知客户端授权失效。
- Codex App Server、Agent Runtime、MCP 工具、Worker/Session/Task 管理。
- VFS、聊天消息、扩展后台 IPC、云端同步和远程文件服务。
- 文件内容全文搜索、二进制预览、跨目录移动、自动合并冲突和后台自动保存。
- 默认开放局域网访问或由服务替用户执行任意命令。

## 15. 实施前需锁定的设计参数

下列参数需在实现计划中定值，并写入协议/运维文档：

1. 服务打包和安装方式，以及系统文件夹选择器的具体实现。
2. 默认端口和是否支持端口自动分配；扩展如何发现实际端口。
3. Chrome/Firefox 扩展来源校验策略及开发模式配置。
4. 一次性配对码的呈现方式、过期时间和客户端凭据安全存储位置。
5. 文件大小、消息大小、搜索结果、目录项、连接数及速率限制。
6. 版本标识算法、原子写入的跨平台实现和混合换行保真策略。
7. 忽略规则语法、默认建议规则和 watcher 溢出后的恢复边界。
8. 目录选择器在无交互桌面/服务会话下不可用时的明确回退行为。
